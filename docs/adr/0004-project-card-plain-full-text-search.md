# Search Project Card with plain full-text, not embeddings

Project Card search matches free-text queries (often Thai, sometimes English) against `client`, `project_name`, and an AI-generated bilingual `description`. We're using plain Postgres keyword/full-text search over those fields rather than embeddings/pgvector, even though the original examples that motivated this feature required true semantic matching (query terms never appearing literally in the source). That requirement no longer applies: the description field is a short, AI-authored summary generated at index time, not raw document text, so its vocabulary can be steered up front to include the terms a user is likely to search in both languages. Plain full-text search over a controlled vocabulary avoids the operational cost of an embeddings pipeline; revisit with pgvector only if literal-keyword misses turn out to be common in practice.
