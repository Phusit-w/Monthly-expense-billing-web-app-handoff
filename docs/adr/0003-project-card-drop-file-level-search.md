# Scope Project Card v1 to project-level metadata, not file-level search

The original idea for the network-share search tool included two capabilities: project-level search (find the right project folder) and file-level search (find a specific, often opaquely-named file inside a project, matched by content/meaning). We dropped file-level search entirely for v1 — each Project Card just carries a `folder_path` back to the share for manual navigation. Grilling the actual pain point showed the user only needed to know what a project is, who it's for, its budget, and its year; full-text indexing and content-matching across ~34,000 files (135GB, mixed `.pdf`/`.doc`/`.docx`/scanned images/CAD) is a much larger system than that requires. If file-level search is wanted later, it's a separate phase built on top of the Project Card catalog, not a v1 stretch goal.
