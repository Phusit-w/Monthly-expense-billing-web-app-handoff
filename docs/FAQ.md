# คำถามที่พบบ่อย

รวมคำอธิบายแนวคิดพื้นฐานที่ถามกันบ่อย ระหว่างทำความเข้าใจโปรเจกต์นี้ (ไม่ใช่ขั้นตอนทำงาน — ขั้นตอนจริงดูที่ `DEV-START.md`/`DEPLOY.md`/`DEPLOY-WINDOWS.md`)

## dev mode กับ production mode ต่างกันยังไง

| | `npm run dev` | `npm run build` + `npm run start` |
|---|---|---|
| ความเร็วโค้ด | ช้ากว่า (ไม่ optimize) | เร็วกว่า |
| แก้โค้ดแล้วเห็นผลทันที | ✅ | ❌ ต้อง build ใหม่ |
| **บังคับ login** (`proxy.ts`) | ❌ ข้ามไปเลย | ✅ บังคับเสมอ |
| database ที่ใช้ | เหมือนกันทั้งคู่ — กำหนดจาก `DATABASE_URL` ใน `.env` เท่านั้น ไม่เกี่ยวกับโหมดนี้ |

บนเซิร์ฟเวอร์จริงใช้ production mode เสมอ ไม่มีใครใช้ `npm run dev` บนเซิร์ฟเวอร์จริง

## Node.js กับ Next.js ต่างกันยังไง

- **Node.js** = ตัวรันโปรแกรม (runtime) ต้องติดตั้งลงเครื่องแยกต่างหาก เหมือน Java Runtime/.NET Runtime
- **Next.js** = เฟรมเวิร์กที่ใช้เขียนแอปนี้ เป็นแค่โค้ด/ไลบรารีที่มากับตัวแอปตอน build ไม่ใช่ซอฟต์แวร์ที่ต้องติดตั้งแยก

```
เซิร์ฟเวอร์ → Node.js (ติดตั้งแยก) → รันไฟล์ที่ Next.js build ออกมาให้
```

Prisma ก็อยู่ในหมวดเดียวกับ Next.js — เป็นไลบรารีที่มากับแอป ไม่ต้องติดตั้งแยก

## LTS คืออะไร

**Long-Term Support** — เวอร์ชันซอฟต์แวร์ (เช่น Node.js) ที่นิ่งแล้ว ได้รับแพตช์ความปลอดภัยต่อเนื่องหลายปีโดยไม่เปลี่ยนพฤติกรรมกะทันหัน เหมาะกับใช้บนเซิร์ฟเวอร์จริง ต่างจาก "Current" ที่เป็นเวอร์ชันล่าสุดแต่เปลี่ยนแปลงบ่อย ไม่เหมาะ production

## ลืมรหัสผ่าน/อยากเปลี่ยนรหัสผ่าน ทำยังไง

ไม่มีหน้าเปลี่ยนรหัสผ่านในตัวเว็บ (ดูรหัสเดิมไม่ได้อยู่แล้วเพราะเก็บเป็น hash) ต้อง "ตั้งรหัสใหม่ทับ" ผ่าน Prisma Studio เท่านั้น — ขั้นตอนเต็มดูที่ `DEPLOY.md`/`DEPLOY-WINDOWS.md` หัวข้อ "การเพิ่มผู้ใช้"

## ถ้าหลายคนใช้ username เดียวกันพร้อมกัน จะเป็นอะไรไหม

ไม่ error ไม่ชนกัน (ระบบไม่เช็คว่า username นี้ login ที่ไหนอยู่บ้าง แต่ละคนได้ cookie ของตัวเอง) **แต่เสียจุดประสงค์ของ audit trail** — "สร้างโดย/แก้ไขล่าสุดโดย" จะขึ้นชื่อเดียวกันหมด แยกไม่ออกว่าใครทำจริง ไม่แนะนำให้แชร์ username — ควรให้ทุกคนมีบัญชีของตัวเอง

การป้องกันไม่ให้ 2 คนบันทึกทับกันเงียบๆ (optimistic locking ผ่าน `updatedAt`) ยังทำงานอยู่เสมอไม่ว่าจะใช้ username เดียวกันหรือคนละบัญชี
